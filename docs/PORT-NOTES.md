# Port notes: Clifton build → riversidefamilyeyecare

Brief for the build agent that will fork the Clifton Eye Center pipeline (`~/cliftoneyecenter-reforge`, called **R** below) into this
workspace. It covers every extraction rule, selector, marker and regex that `R/src/build.mjs` and
`R/src/lib/{content,forms,home,seo,images,templates,util}.mjs` depend on, measured against BOTH raw corpora, and it records what R's
libraries do when they run UNMODIFIED over all 148 Riverside pages. Method and layout follow `R/docs/PORT-NOTES.md` (sections 0-4 and
Appendix A). R was only read. Nothing under `src/` here was written: the fork happens later.

## 0. How the numbers were produced

- **Reference code read in full:** build.mjs 1211 lines, content.mjs 821, forms.mjs 173, home.mjs 439, seo.mjs 191, images.mjs 101,
  templates.mjs 430, util.mjs 127, plus `src/content/{chrome,site-map,image-plan}.json`. Intent from `R/docs/{PORT-NOTES,BUILD-NOTES,
  BUILD-DECISIONS}.md` and the `R/docs/COMPONENTS.md` outline. Line numbers below (Lnnn) are R's.
- **Census** (`tmp/wf1/port/census.mjs` → `census.json`): 228 regex markers (the ones content.mjs, build.mjs and home.mjs key on, the
  forms/SEO/chrome rules, and the Riverside candidates), plus 72 class/attribute literals grepped out of the pipeline sources, every
  `fl-module-*` class (27 here, 23 there), every `ecp-*` class (400 here, 561 there; 202 / 163 inside `<main>`), Gravity Forms ids and
  field types, iframe hosts and bracketed tokens in visible text. **here** = `audit/raw/*.html` (148 files), **there** =
  `R/audit/raw/*.html` (349 files). Cells read "files (hits)". Regions are R's: `markup` is the raw HTML minus `<script>`, `<style>` and
  comments; `main` is `<main…>…</main>` of the markup; `sidebar` runs from `div.ecp-secondary` to the footer wrapper; `header`, `footer`,
  `head` are the landmarks; `doc` is the raw bytes; `text` and `maintext` are markup and main with the tags removed.
- **Harness** (`tmp/wf1/port/harness/`). `lib/` holds byte copies of R/src/lib/*.mjs (sha256 equal to R at copy time: content
  `c28f1c9b`, forms `15dc8fcf`, home `6a195b43`, images `5d8b3011`, seo `dee0ad7f`, templates `9f60f94c`, util `81f77322`). `stub/`
  holds R's `chrome.json`, `site-map.json`, `image-plan.json` and `audit/image-classification.json` (Riverside has none of them).
  `driver.mjs` is GENERATED by `make-driver.mjs` from a byte copy of R/src/build.mjs (`ref/build.mjs.txt`, sha256 `ba899b08bbb9c0d2…`)
  plus 21 patches, each asserted to match exactly once (`patches.json`). The patches only: skip the cwebp encode (an image record
  carries its local file name and real dimensions); record the build's top-level throws instead of throwing; swap `chrome.origin`
  to the Riverside origin (`--origin-as-is` keeps Clifton's); skip the static-asset and report sections; keep every write under
  `tmp/wf1/port/`. `buildPage`, `renderComp`, the home fallback and the head/SEO code run verbatim. Outputs: `harness-out/<savedAs>`
  (the `<main>` build.mjs would emit for each page), `harness-dist/` (full pages, with Clifton chrome), `harness.json` (per-page
  records, failures, stat deltas) and the `--origin-as-is` twins (`harness-out-asis/`, `harness-asis.json`). A supplementary mode,
  `--riverside-inputs`, reads the Riverside `src/content/chrome.json` and `audit/image-classification.json` that another agent wrote
  during this run (0.3); its outputs end in `-rv`.
- **Coverage** (`tmp/wf1/port/coverage.mjs` → `coverage.json`). The method of `tools/sentence-parity.mjs` (R's tool, copied to P
  unchanged): split the raw page at block elements into sentences of ≥ 5 words, normalise quotes, dashes and whitespace, and count a
  sentence found when it appears in the output text. Its helper functions are copied byte for byte and re-checked against the tool on
  every run. The first run failed that check (a U+00A0 literal in `norm` had become a plain space in my copy), so the line is spliced
  from the tool. Added here: each source sentence is located in the raw page (content region = `<main>`, or `<body>` on the 6 pages
  without one; sidebar = `div.ecp-secondary`; header = `header.ecp-header`; footer = `div.ecp-footer-wrapper`) and, inside the content
  region, in its innermost platform module, which is how every loss is classified. Two checks the tool does not make: every text run of
  the content region (any length), and occurrence counts of repeated sentences. Positive control: a found sentence deleted in memory
  must come back lost (it fired, on `/`). That control only checks that the deletion removed the string; the verification re-scored
  a mutated page instead, and it fired too (Verification record).
- **Everything else** cited below comes from `tmp/wf1/port/facts.mjs` → `facts.json` (home rows, aliases, MOVED and artefact effects,
  path-keyed tables, images, identity inputs, baseline captures, chrome strings, widgets, form fields), `chrome-variants.mjs`,
  `runs-breakdown.mjs`, `entity-check.mjs`, and `view.mjs` (a text outline of one output page). No request was made to the live site
  or its CDN.
- **The Clifton column** of 0.1 is `R/audit/build-report.json` (R's shipped build, on R's own inputs), except the main/body split, which
  the report does not carry (census A1 / A.8). It is the positive control for the extractors: anything that reports 0 here fires there.
- **Families** in 0.2 are this note's grouping (`coverage.mjs familyOf`: URL section plus `body.single-post`). No Riverside
  `site-map.json` exists yet, so they are UNVERIFIED against the architecture agent's partition.
- **Legend.** KEEP: carries over unchanged. ADAPT: must change (the change is stated). DROP: delete (Clifton-only, wrong here, or 0 hits
  here and no use). NEW: a Riverside marker with no rule yet. "(inert)" marks a rule with 0 hits here that may stay at no cost.
  "Lnnn" after an R file is a line number; an id such as L8 or L21 beside a count is a census marker (Appendix A); "L10" / "L11"
  beside R's `chrome.json` or Clifton's removals are R's ledger change ids.

```
node tmp/wf1/port/gen-appendix.mjs tmp/wf1/port/census.json docs/PORT-NOTES.md
```
